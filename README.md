# Mini S3 - AWS S3 핵심 기술 구현 (C)

AWS S3가 하드디스크로 초당 1PB를 처리하는 핵심 기술 3가지를 C로 구현한 시뮬레이터.

## 구현된 기술

### 1. 데이터 분산 저장 (Data Striping)
데이터를 잘게 쪼개서 여러 디스크에 분산 저장 → 병렬 읽기/쓰기로 속도 N배 향상.

### 2. Power of Two Choices
디스크를 랜덤 2개 골라서 사용률이 낮은 쪽에 저장. 단순하지만 분포가 극적으로 균등해진다.

### 3. 이레이저 코딩 (Erasure Coding)
Reed-Solomon 코드(Cauchy 행렬 + GF(256))로 패리티 조각을 생성.
5개 데이터 + 4개 패리티 = 9개 조각 중 아무 5개만 있으면 원본 복구 가능.
단순 복제(2배) 대비 1.8배만 용량이 늘어나면서 더 높은 내결함성 제공.

## 빌드 & 실행

```bash
make        # 빌드
make run    # 데모 실행
make test   # 종합 실험 실행
make clean  # 정리
```

## 파일 구조

```
gf256.h / gf256.c      - GF(256) 갈루아 필드 연산 (이레이저 코딩의 수학적 기반)
erasure.h / erasure.c   - Reed-Solomon 이레이저 코딩 (Cauchy 행렬 기반 MDS 코드)
main.c                  - 3가지 기술 데모
test.c                  - 종합 실험 및 벤치마크 (10개 항목)
Makefile                - 빌드 설정
```

### [6] 읽기 꼬리 지연시간

정상 디스크 1-5ms, 지연 디스크(5% 확률) 50-200ms 시뮬레이션. 100,000회 시행.

| 백분위 | 기본 (5개 대기) | 헤지 (9개 중 5개) | 개선율 |
|--------|---------------|------------------|--------|
| P50 | 5.0 ms | 3.0 ms | 40.0% |
| P90 | 137.0 ms | 4.0 ms | **97.1%** |
| P95 | 169.0 ms | 4.0 ms | **97.6%** |
| P99 | 195.0 ms | 5.0 ms | **97.4%** |
| P99.9 | 200.0 ms | 5.0 ms | **97.5%** |

핵심: 이레이저 코딩을 활용한 헤지 읽기로 P99 지연시간이 **195ms → 5ms** (97% 감소). 느린 디스크를 기다리지 않고 다른 조각으로 우회.

### [7] 저장 방식 효율 비교

| 방식 | 저장 배율 | 내결함성 (디스크) | 최소 디스크 |
|------|----------|-----------------|------------|
| 복제 없음 | 1.0x | 0 | 1 |
| 2중 복제 | 2.0x | 1 | 2 |
| 3중 복제 | 3.0x | 2 | 3 |
| **RS(5,4) - S3 방식** | **1.8x** | **4** | **9** |
| RS(10,4) | 1.4x | 4 | 14 |
| RS(16,4) | 1.25x | 4 | 20 |

RS(5,4): 3중 복제 대비 **40% 적은 용량**으로 **2배 높은 내결함성**.

### [8] 내구성(Durability) 분석

Markov 체인으로 MTTDL(Mean Time To Data Loss)을 해석적으로 계산. Monte Carlo 이산 사건 시뮬레이션(100만회)으로 공식 검증 후 실제 파라미터에 적용.

AFR=2%, Rebuild=24시간:

| 방식 | MTTDL (년) | 연간 손실 확률 | 내구성 (9s) |
|------|-----------|--------------|------------|
| 단일 디스크 | 4.95e+01 | 2.00e-02 | 1.7 |
| 2중 복제 | 4.47e+05 | 2.24e-06 | 5.7 |
| 3중 복제 | 5.39e+09 | 1.86e-10 | **9.7** |
| **RS(5,4) S3 방식** | **8.26e+15** | **1.21e-16** | **15.9** |
| RS(10,4) | 5.31e+14 | 1.88e-15 | 14.7 |

핵심: RS(5,4)는 **15.9 nines** — 3중 복제(9.7 nines) 대비 **백만 배** 더 안전. AWS의 "11 nines" 주장은 디스크 고장 외 요인(소프트웨어 버그, 재해 등)까지 포함한 수치.

Monte Carlo 검증 (AFR=20% 가속, 100만 시행):

| 방식 | 분석적 예측 | MC 실측 | 오차 |
|------|-----------|---------|------|
| 단일 디스크 | 20.0000% | 20.0152% | 0.1% |
| 2중 복제 | 0.0272% | 0.0245% | 10.0% |
| RS(2,1) | 0.0816% | 0.0804% | 1.4% |

### [9] CRC32 Silent Corruption 탐지

디스크가 고장이 아니라 **조용히 잘못된 데이터를 반환**하는 경우(bit rot, firmware 버그). 인코딩 후 1~3개 조각에 1~3바이트 랜덤 변조 시뮬레이션.

| 항목 | 결과 |
|------|------|
| CRC32 탐지율 | 999/1000 (99.9%) |
| 탐지 후 복구 | 1000/1000 (100%) |

체크섬 없이는 손상 데이터가 정상으로 반환될 위험. **CRC32 + 이레이저 코딩 = 감지 + 복구 모두 가능**.

| 1h | 5.32e-12 | 1.98e-21 | 2,685,933,369 |
| 6h | 1.91e-10 | 2.57e-18 | 74,612,874 |
| 24h | 3.06e-09 | 6.57e-16 | **4,664,118** |
| 72h | 2.76e-08 | 5.32e-14 | 518,476 |
| 168h (1주) | 1.50e-07 | 1.57e-12 | 95,319 |
| 720h (1달) | 2.75e-06 | 5.28e-10 | 5,217 |

핵심: 24시간 rebuild 기준, RS(5,4)는 3중 복제 대비 **460만 배** 안전. Rebuild 시간이 길어질수록 이레이저 코딩의 우위가 더 커진다.
